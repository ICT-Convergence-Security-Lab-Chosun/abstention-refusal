# Abstention is not Refusal — Paper Code

Code for the paper *"Abstention is not Refusal, but it Affects Safety of Large Language Models."*
It covers the full pipeline: geometry of the abstention (`v_abs`) vs refusal (`v_ref`) directions,
cross-task abstention induction/suppression, response frames, the reverse-steering jailbreak,
operating-point selection, and human validation.

This is a **from-scratch** release: no benchmark text or model outputs are shipped. The public
source datasets are fetched by a script; the pipeline then runs from model weights (GPU) and an
OpenAI-compatible API for the LLM judge. It reproduces the *method* and gives results close to the
paper; it does **not** reproduce the paper's exact frozen item selection (see "What reproduces").

---

## Quick start

```bash
# 0. environment
conda env create -f environment.yml          # or: pip install -r requirements.txt
conda activate abstention-paper
export ABST_PKG=$(pwd)                        # repo root (scripts resolve paths from here)
export HF_HOME=/path/to/hf_cache             # model-weight + dataset cache

# 1. API key for the LLM judge (gpt-4o-mini via an OpenAI-compatible endpoint)
cp .env.example .env.local                    # then edit: OPENROUTER_API_KEY=sk-or-v1-...

# 2. fetch the public datasets into data/
python3 scripts/prepare_data.py

# 3. per-model pipeline (repeat for each MODEL_KEY), then the cross-model analyses
export RUN_ID=v2_llama31_8b MODEL_KEY=llama31_8b_instruct
for s in scripts/v2/0*.sh scripts/v2/1*.sh; do bash "$s"; done
```

Requirements: Python 3.11, a CUDA GPU for the extraction/generation stages, and network access for
the dataset fetch and the API judge. Pinned versions are in `requirements.txt` / `environment.yml`.

## 1. Fetch the datasets — `scripts/prepare_data.py`

Downloads the public sources into `data/` (nothing is redistributed in this repo):

| File written | Contents | Source |
|---|---|---|
| `squad2_umwp_falseqa_rawq_normalized.jsonl` | SQuAD 2.0 + UMWP + FalseQA (answerable + unanswerable) | HF `rajpurkar/squad_v2`; GitHub `Yuki-Asuuna/UMWP`, `thunlp/FalseQA` |
| `advbench_harmful.jsonl` | AdvBench harmful prompts (refusal-direction extraction) | HF `walledai/AdvBench` |
| `alpaca_harmless.jsonl` | Alpaca benign prompts (benign contrast) | HF `tatsu-lab/alpaca` |

Each row carries `sample_id`, `question`, `dataset`, `should_abstain`. Set `PREPARE_PER_DATASET=N`
to cap rows per benchmark (default 3000). Licenses and the responsible-use notice are in
[`DATA_LICENSES.md`](DATA_LICENSES.md); the `sample_id` scheme is in
[`DATA_PROVENANCE.md`](DATA_PROVENANCE.md). TriviaQA (the answerable control) is generated by step 00.

## 2. Per-model pipeline — `scripts/v2/00..10`

Configuration comes from `configs/v2_defaults.env`; override per run with environment variables:

| Variable | Meaning | Default |
|---|---|---|
| `RUN_ID` | output namespace under `runs/` | `v2_paper_llama31_8b` |
| `MODEL_KEY` | model to run (`src/steering/instruction_config.py`) | `llama31_8b_instruct` |
| `DATA_DIR` | dataset directory | `data` |
| `JUDGE_MODEL` | LLM judge id | `openai/gpt-4o-mini` |
| `CUE_LIMIT_PER_DATASET` | cue items per dataset (500 → 1500 total) | unset (all) |
| `SEED` | split / sampling seed | `42` |

```bash
export RUN_ID=v2_llama31_8b MODEL_KEY=llama31_8b_instruct

bash scripts/v2/00_generate_controlled_test.sh   # controlled TriviaQA pool (API)   -> runs/$RUN_ID/controlled/
bash scripts/v2/01_prepare_splits.sh             # cue_extract / dev / test (seeded) -> runs/$RUN_ID/splits/
bash scripts/v2/02_extract_vectors_geometry.sh   # cue_diff -> SVD -> comp1 (v_abs)  -> runs/$RUN_ID/vectors/
bash scripts/v2/02b_extract_refusal_vectors.sh   # AdvBench - Alpaca -> v_ref        -> runs/$RUN_ID/vectors/
bash scripts/v2/03_build_calibration_jobs.sh     # steering jobs
bash scripts/v2/04_run_calibration_generation.sh # steered generations (GPU)         -> runs/$RUN_ID/generations/
bash scripts/v2/05_judge_calibration.sh          # LLM judge (gpt-4o-mini)            -> runs/$RUN_ID/api_judge/
bash scripts/v2/06_select_params.sh              # operating point (L*, c*)
bash scripts/v2/07_build_eval_jobs.sh            # eval jobs at (L*, c*)
bash scripts/v2/08_run_eval_generation.sh        # eval generations (GPU)
bash scripts/v2/09_judge_eval.sh                 # LLM judge on eval
bash scripts/v2/10_summarize_plot.sh             # per-model summary
```

Each stage reads the previous stage's output under `runs/$RUN_ID/` and writes the next; the split
files carry the item text, so 02+ need no re-fetch.

## 3. Cross-model analyses — the paper numbers

The LLM judge everywhere is `src/analysis/ml_judge.py` (gpt-4o-mini).

```bash
# §4.1 geometry: cos(v_abs,v_ref), |cos|(cue_diff,v_abs), SVD PVE
python3 src/analysis/geometry_final.py

# §4.2 induction / suppression (Table 7)
bash scripts/run_v1sel_generation.sh && bash scripts/run_supp_v1sel_generation.sh
bash scripts/run_judge_v1sel.sh       && bash scripts/run_judge_supp_v1sel.sh

# §4.2 response frames (Fig 4)
python3 src/analysis/compute_frames.py

# §4.3 reverse-steering jailbreak, validity-gated non-refusal (Table 8);
#   generations judged by WildGuard (src/analysis/wildguard_harm_check.py)
python3 src/analysis/compute_nonref_valid.py

# Table 5 operating points: Stage-A layer sweep and Stage-B dose
python3 src/analysis/judge_joint_sweep.py && python3 src/analysis/analyze_joint_sweep.py
python3 src/analysis/judge_dose.py        && python3 src/analysis/analyze_comp1_dose.py
```

## 4. Human validation (Table 6)

```bash
python3 src/analysis/build_human_audit_200.py                        # blinded 200-item sheets -> human_label_200/
# a human fills the [TAG]: labels in human_label_200/*.md (blinded to model / condition / verdict)
python3 src/analysis/score_human_audit_200.py --dir human_label_200  # agreement / kappa
```

The builder is deterministic (`seed=20260804`); the labels are the human input.

## What reproduces

- The full method runs end-to-end from the fetched public data.
- Numbers are **close to, not identical to**, the paper: `01_prepare_splits` draws cue/dev/test by
  a fixed seed from the raw public pool rather than the paper's normalized/curated pool, so the
  exact items differ. Judge and steering are otherwise as described in the paper.
- Model availability: `instruction_config.py` references several open models; some gated releases
  may require HuggingFace access approval to reproduce those arms.

## Layout

```text
scripts/prepare_data.py   fetch the public datasets into data/
scripts/v2/               00–10 per-model pipeline
scripts/                  cross-model generation / judge drivers
src/steering/             extraction, steering, campaign runner, selection
src/analysis/             geometry, LLM + WildGuard judges, sweep/dose analysis, number reproducers, human-audit build+score
configs/v2_defaults.env   run configuration (models, paths, judge = gpt-4o-mini)
```

Outputs are written under `runs/` and `data/`, both git-ignored.

## Data, licenses, and responsible use

No benchmark inputs or model generations are shipped; `scripts/prepare_data.py` fetches the public
datasets, each under its own license — see [`DATA_LICENSES.md`](DATA_LICENSES.md). The
reverse-steering experiment applies AdvBench harmful prompts and produces unsafe model outputs when
refusal is broken; those outputs are generated locally at run time and are **not** included here.
